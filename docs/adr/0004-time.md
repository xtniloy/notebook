# ADR 0004: Time

- **Status:** Accepted
- **Date:** 2026-10-29
- **Task:** 2.1

## Context

Time decides a lot of behaviour: note dates and sorting, date sections in the
note list (task 1.6), autosave, the 30-day purge of Recently Deleted, auto-relock
of locked notes after inactivity, and sync tombstones. Notes move between
devices in different time zones (Plan §9), and users change zones when they
travel.

Most of these rules are about days or weeks, so tests must be able to move time
forward without waiting.

## Options

- **A: `QDateTime` everywhere,** stored as ISO 8601 text. Readable, but text
  comparison, time zone suffixes, and parsing cost in a 10,000-row list.
- **B: Local time as integers.** Breaks when the user changes zone, and on
  daylight saving transitions (duplicate or missing hours).
- **C: UTC milliseconds since the Unix epoch, as `int64`,** read through an
  injectable clock.

## Decision

**Option C.**

- Every stored or transmitted timestamp is **UTC milliseconds since
  1970-01-01**, as `qint64` in C++ and `INTEGER` in SQLite (`created_at`,
  `updated_at`, `trashed_at`, `deleted_at`, ...). Names end in `At` / `_at`
  (or `Ms` where the unit isn't obvious).
- **All code reads the current time through `IClock::nowMs()`** (task 2.2).
  The app passes a `SystemClock` (`QDateTime::currentMSecsSinceEpoch()`); tests
  pass `FakeClock` (`tests/common/`), which can jump forward. Direct calls to
  `QDateTime::currentDateTime()`, `currentMSecsSinceEpoch()` or `time()` outside
  `SystemClock` are not allowed in `src/` (checked in review; a grep check can
  be added to CI later).
- Conversion to local time happens **only for display**, at the UI edge, with
  an explicit time zone (as `DateGrouping` already does), so the same note shows
  the right local date in any zone.
- Durations are computed from `nowMs()` differences. Event-loop timing that has
  no meaning across restarts (the 500 ms autosave debounce, the 150 ms fade) may
  use `QTimer` directly.

## Consequences

- Sorting and range queries are integer comparisons, covered by indexes such as
  `idx_notes_folder (folder_id, updated_at DESC)`.
- Purge and relock logic is testable in milliseconds: `FakeClock::advance(30 days)`.
- The wall clock can jump (NTP, manual changes). Security rules must fail safe:
  if the elapsed time since the last activity is **negative**, auto-relock
  treats it as expired (task 6.5).
- Timestamps from other devices can be wrong by minutes or more. Sync uses each
  record's `version` counter to detect changes, and uses `updated_at` only to
  pick which copy stays the main one in a conflict; both copies are kept either
  way (Plan §9.5), so clock skew can't lose data.
- `int64` milliseconds cover ±292 million years; no overflow concerns.

## Verification

- `TC-STO-001`: `FakeClock::advance(30 days)` changes `nowMs()` by exactly that amount.
- `TC-UI-014`: date sections use calendar days in the given time zone, including
  across a daylight saving change.
- Phase 2 trash and Phase 6 relock tests run on `FakeClock`.
